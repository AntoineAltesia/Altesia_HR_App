Protéger une page

Chiffre un fichier HTML avec un mot de passe. Le fichier produit ne contient plus votre page en clair : sans le mot de passe, il n'y a rien à lire, même en ouvrant le code source sur GitHub.

1

La page à protéger

Par exemple Altesia_RH_competences.html.

2

Le mot de passe

Il ne sort pas de cette page et n'est écrit nulle part. Personne ne peut le retrouver, moi non plus : s'il est perdu, le fichier protégé est définitivement illisible. Gardez l'original de côté.

3

Le fichier à déposer sur GitHub

GitHub Pages sert index.html à l'adresse du dépôt.

Ce que cette protection fait, et ne fait pas

  • Le contenu est chiffré (AES-GCM 256 bits, clé dérivée du mot de passe par PBKDF2, 310 000 itérations). Le fichier publié ne contient que du texte chiffré : ni votre référentiel, ni votre code ne sont lisibles sans le mot de passe.
  • Le mot de passe doit être long. Le fichier étant public, il peut être essayé hors ligne, autant de fois que voulu. Une phrase de quatre ou cinq mots vaut mieux qu'un mot compliqué de huit caractères.
  • Qui a le mot de passe a tout. Il peut enregistrer la page déchiffrée et la rediffuser. Changer le mot de passe suppose de reprotéger la page et de la redéposer — les copies déjà téléchargées, elles, restent lisibles.
  • Les données saisies dans l'app ne sont pas concernées : elles restent dans le navigateur de la machine, jamais dans le fichier ni sur GitHub.
  • Pour un secret qui engage le cabinet, cela reste une page publique chiffrée, pas un espace privé. Un dépôt privé ou un partage interne reste plus sûr.
